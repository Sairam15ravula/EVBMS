# Plan 05-02: Client WebSocket Service, API Vehicle Comparison & Grounded AI Doctor

**Phase**: 5 (Cell-Level Monitoring & Dashboard Enhancement)  
**Plan**: 05-02  
**Goal**: Build a React WebSocket client service (`src/services/telemetrySocket.ts`), integrate live stream into `EvBmsPlatform.tsx` without full re-renders, connect `BmsComparison.tsx` to backend vehicle APIs, and polish Digital Doctor AI assistant drawer.

## Requirements Addressed
- **UI-02**: Real-time dashboard view with WebSocket telemetry updates, dynamic metric cards, and alert notifications.
- **UI-03**: Advanced degradation & RUL projection analytics view with interactive scenario controls and Recharts visualizations.
- **UI-04**: Digital Doctor AI diagnostic assistant drawer with conversation history and context-aware troubleshooting suggestions.
- **UI-05**: Multi-vehicle comparison view allowing side-by-side battery health and degradation analysis.

## Explicit Technical Constraints
1. WebSocket client service (`telemetrySocket.ts`) runs strictly in React (Express owns WS server).
2. Live telemetry streams over WebSocket; historical telemetry data uses FastAPI `GET /api/telemetry/history/{vehicle_id}` REST endpoint.
3. `BmsComparison.tsx` fetches vehicles from `/api/vehicles` REST API.
4. Scenario controls are labeled "Simulations / Estimated Impact".
5. Digital Doctor consumes evidence produced by physics/ML backend without inventing unsupported diagnoses.
