# Plan 01-02: SQLAlchemy ORM Models, TimescaleDB Hypertables & Repository Layer

**Phase**: 1 (Database Persistence & Data Architecture)  
**Plan**: 01-02  
**Goal**: Build core SQLAlchemy 2.0 async ORM models, TimescaleDB hypertable migration scripts, Pydantic model converters, and repository data access layer.

## Requirements Addressed
- **DATA-01**: PostgreSQL database schema configured with Alembic migrations for user accounts, vehicle assets, battery packs, and diagnostic alert logs.
- **DATA-02**: Time-series telemetry storage (TimescaleDB hypertable or partitioned table) for continuous voltage, current, temperature, and SoC/SoH samples.
- **DATA-03**: Data access layer / ORM (SQLAlchemy 2.0 async) connecting FastAPI backend services to database.

## Files Modified & Created

### New Files
- `backend/db/models.py` — SQLAlchemy 2.0 ORM model classes (`UserModel`, `VehicleModel`, `BatteryPackModel`, `TelemetryFrameModel`, `AlertLogModel`)
- `alembic/versions/001_initial_schema.py` — Initial migration revision adding core tables and converting `telemetry_frames` to TimescaleDB hypertable
- `backend/db/repositories/base.py` — Generic Async SQLAlchemy repository base class
- `backend/db/repositories/user_repo.py` — User data access layer
- `backend/db/repositories/vehicle_repo.py` — Vehicle asset & battery pack data access layer
- `backend/db/repositories/telemetry_repo.py` — Telemetry hypertable time-series data access layer (batch inserts, time-bucket aggregation)

### Modified Files
- `backend/app.py` — Connect startup event to verify database initialization

## Tasks

### Task 1: Create SQLAlchemy 2.0 ORM Models
- Build `UserModel` (`id`, `email`, `hashed_password`, `role`, `created_at`).
- Build `VehicleModel` (`id`, `name`, `model`, `chemistry`, `pack_capacity_kwh`, `nominal_voltage`, `owner_id`).
- Build `BatteryPackModel` (`id`, `vehicle_id`, `serial_number`, `initial_capacity_ah`, `cell_count`).
- Build `TelemetryFrameModel` (`timestamp`, `vehicle_id`, `voltage`, `current`, `temperature`, `soc`, `soh`, `internal_resistance`, `cell_voltages`, `active_anomalies`).
- Build `AlertLogModel` (`id`, `timestamp`, `vehicle_id`, `severity`, `fault_code`, `description`, `acknowledged`).

### Task 2: Create Migration Revision & Hypertable SQL
- Create Alembic revision `001_initial_schema.py` containing table definitions and execute SQL `SELECT create_hypertable('telemetry_frames', 'timestamp', if_not_exists => TRUE);`.

### Task 3: Build Repository Access Layer
- Implement `BaseRepository` with common CRUD methods (`get_by_id`, `create`, `update`, `delete`).
- Implement `TelemetryRepository` with optimized time-bucket aggregation methods for chart telemetry rendering and high-frequency batch insertion.

## Verification Criteria
1. `alembic upgrade head` creates all tables and hypertable in PostgreSQL without errors.
2. `TelemetryRepository.insert_batch()` successfully inserts telemetry frames into database.
3. `TelemetryRepository.get_time_buckets()` aggregates telemetry metrics cleanly over specified time intervals.
