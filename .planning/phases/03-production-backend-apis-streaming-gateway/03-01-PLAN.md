# Plan 03-01: Express WebSocket Telemetry Gateway, Throttling & Aggregated Health

**Phase**: 3 (Production Backend APIs & Streaming Gateway)  
**Plan**: 03-01  
**Goal**: Integrate real-time WebSocket telemetry streaming into the Node Express gateway (`server.ts`), add HTTP rate limiting & WebSocket connection throttling, and expose an aggregated gateway health endpoint.

## Requirements Addressed
- **BACK-02**: Real-time battery telemetry streaming server via WebSockets in Node/Express.
- **BACK-04**: Health check, metrics, and rate limiting middleware across Express and FastAPI services.

## Explicit Architectural Constraints
1. Express is the real-time WebSocket gateway.
2. WebSocket (`/ws/telemetry`) is the ONLY real-time transport (no SSE).
3. Telemetry frames broadcasted over WebSocket conform 1:1 to Phase 1 `TelemetryFrameModel` / `BatteryTelemetry` schema.
4. Telemetry generated by the gateway engine is broadcast over WebSocket and persisted to the database via FastAPI / `TelemetryRepository`.
5. Express `GET /api/health` aggregates gateway metrics (uptime, active WS connections, connection limits) and proxied FastAPI DB / ML readiness.
6. HTTP rate limiting (`express-rate-limit`: max 100 req/15min) applies to REST endpoints; separate connection limits (max 50) and per-socket message rate limits (10 msg/sec) apply to WebSocket connections.

## Files Modified & Created

### New Files
- `src/services/websocketServer.ts` — WebSocket server manager for live telemetry streaming, connection capping, and message rate limit enforcement

### Modified Files
- `server.ts` — Wrap Express in HTTP server, register WebSocket handler, add `express-rate-limit` middleware, and implement `/api/health`
- `package.json` — Add `ws`, `@types/ws`, `express-rate-limit` dependencies

## Tasks

### Task 1: Add Gateway Dependencies
- Add `ws`, `@types/ws`, and `express-rate-limit` to `package.json`.

### Task 2: Create WebSocket Telemetry Streaming Manager
- Create `src/services/websocketServer.ts` managing client connections to `/ws/telemetry`.
- Enforce max 50 concurrent client connections and 10 msg/sec rate limit per client.
- Broadcast live telemetry frames at 1-second intervals using single authoritative schema (`BatteryTelemetry`).

### Task 3: Attach WebSocket & Rate Limiter to Express Server
- Update `server.ts` to wrap Express in an `http.Server` instance.
- Add `express-rate-limit` middleware (max 100 requests / 15 mins per IP).
- Implement `GET /api/health` returning aggregated JSON (Express uptime, active WS connections, max connections, and proxied FastAPI database & ML readiness).

## Verification Criteria
1. WebSocket clients can connect to `ws://localhost:3000/ws/telemetry` and receive continuous telemetry JSON messages conforming to `BatteryTelemetry`.
2. Connections exceeding 50 concurrent clients are rejected with code 1013.
3. `GET /api/health` returns aggregated health JSON containing gateway metrics and proxied FastAPI DB/ML readiness.
4. REST requests exceeding 100 per 15 mins are throttled with HTTP 429 status code.
