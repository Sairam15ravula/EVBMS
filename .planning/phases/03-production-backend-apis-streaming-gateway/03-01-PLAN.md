# Plan 03-01: Express WebSocket Telemetry Server, Rate Limiting & Gateway Health

**Phase**: 3 (Production Backend APIs & Streaming Gateway)  
**Plan**: 03-01  
**Goal**: Integrate real-time WebSocket telemetry streaming into the Node Express server (`server.ts`), add rate limiting middleware, and expose gateway health metrics.

## Requirements Addressed
- **BACK-02**: Real-time battery telemetry streaming server via WebSockets or Server-Sent Events (SSE) in Node/Express.
- **BACK-04**: Health check, metrics, and rate limiting middleware across Express and FastAPI services.

## Files Modified & Created

### New Files
- `src/services/websocketServer.ts` — WebSocket server manager for live telemetry streaming

### Modified Files
- `server.ts` — Attach HTTP server, WebSocket handler, and `express-rate-limit` middleware
- `package.json` — Add `ws`, `@types/ws`, `express-rate-limit` dependencies

## Tasks

### Task 1: Add Gateway Dependencies
- Add `ws`, `@types/ws`, and `express-rate-limit` to `package.json`.

### Task 2: Create WebSocket Telemetry Streaming Manager
- Create `src/services/websocketServer.ts` managing client connections to `/ws/telemetry`.
- Broadcast live telemetry frames at 1-second intervals with client disconnection cleanup.

### Task 3: Attach WebSocket & Rate Limiter to Express Server
- Update `server.ts` to wrap Express in an `http.Server` instance.
- Add `express-rate-limit` middleware (max 100 requests / 15 mins per IP).
- Expose `GET /api/health` returning gateway uptime, active WebSocket connection count, and backend service status.

## Verification Criteria
1. WebSocket clients can connect to `ws://localhost:3000/ws/telemetry` and receive continuous telemetry JSON messages.
2. `GET /api/health` returns status JSON with uptime and connection metrics.
3. Express rate limiter blocks excessive requests with HTTP 429 status code.
