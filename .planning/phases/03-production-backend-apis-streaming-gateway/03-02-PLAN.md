# Plan 03-02: FastAPI Production Fleet CRUD, Pack Diagnostics & Alert History APIs

**Phase**: 3 (Production Backend APIs & Streaming Gateway)  
**Plan**: 03-02  
**Goal**: Build FastAPI production REST APIs for vehicle fleet CRUD, battery pack metadata, diagnostic alert history pagination with RBAC authorization, and bounded historical telemetry queries.

## Requirements Addressed
- **BACK-01**: Production-grade FastAPI prediction API endpoints with OpenAPI/Swagger documentation, input validation, and standard HTTP error contracts.
- **BACK-03**: Vehicle fleet management CRUD API endpoints (`/api/vehicles`, `/api/packs`, `/api/alerts`).
- **BACK-04**: Health check, metrics, and rate limiting middleware across Express and FastAPI services.

## Explicit Architectural Constraints
1. FastAPI owns all REST API and ML/application backend endpoints.
2. Reuse Phase 1 `TelemetryFrameModel` schema and repositories (`VehicleRepository`, `TelemetryRepository`, `UserRepository`). Do not create duplicate database access patterns.
3. Telemetry ingestion endpoint `POST /api/telemetry/ingest` persists frames to TimescaleDB via `TelemetryRepository.insert_frame()`.
4. `GET /api/telemetry/history/{vehicle_id}` MUST support bounded date range filtering (`start_time`, `end_time`) and pagination (`limit` max 1000, `offset`).
5. `PATCH /api/alerts/{id}/acknowledge` MUST reuse Phase 2 JWT auth and RBAC middleware (`require_role(["admin", "fleet_manager", "technician"])`).
6. Do not modify unrelated architecture or rewrite working services.

## Files Modified & Created

### New Files
- `backend/routes/vehicles.py` — Vehicle fleet management REST router (`GET /api/vehicles`, `POST /api/vehicles`, `GET /api/vehicles/{id}`, `DELETE /api/vehicles/{id}`)
- `backend/routes/alerts.py` — Alert logs & fault code router (`GET /api/alerts`, `PATCH /api/alerts/{id}/acknowledge`)
- `backend/routes/telemetry.py` — Telemetry ingestion & historical query router (`POST /api/telemetry/ingest`, `GET /api/telemetry/history/{vehicle_id}`)
- `backend/schemas/fleet.py` — Pydantic validation models for vehicles, battery packs, alert logs, and telemetry queries

### Modified Files
- `backend/app.py` — Mount `vehicles_router`, `alerts_router`, and `telemetry_router`

## Tasks

### Task 1: Create Fleet Pydantic Schemas
- Create `backend/schemas/fleet.py` defining schemas for vehicle creation, pack metadata, bounded telemetry query filters (`start_time`, `end_time`, `limit`, `offset`), and alert responses.

### Task 2: Build Fleet & Pack Management Endpoints
- Create `backend/routes/vehicles.py` providing CRUD operations connected to Phase 1 `VehicleRepository`.

### Task 3: Build Telemetry Ingestion & Bounded Historical Query Router
- Create `backend/routes/telemetry.py` with:
  - `POST /api/telemetry/ingest`: Ingest and persist telemetry frame via `TelemetryRepository.insert_frame()`.
  - `GET /api/telemetry/history/{vehicle_id}`: Bounded date range and paginated query via `TelemetryRepository`.

### Task 4: Build Alert Logs Endpoint with Phase 2 RBAC Auth
- Create `backend/routes/alerts.py` with:
  - `GET /api/alerts`: List diagnostic alert logs with pagination and filters.
  - `PATCH /api/alerts/{id}/acknowledge`: Mark alert log as acknowledged requiring `require_role(["admin", "fleet_manager", "technician"])`.
- Mount routers in `backend/app.py`.

## Verification Criteria
1. `GET /api/vehicles` lists vehicle assets from Phase 1 database repository.
2. `GET /api/telemetry/history/{vehicle_id}` retrieves bounded telemetry records with `start_time`, `end_time`, `limit`, and `offset`.
3. `PATCH /api/alerts/{id}/acknowledge` accepts authorized JWT token with `fleet_manager` or `technician` role and rejects `driver` role with 403 Forbidden.
4. FastAPI `/docs` generates interactive Swagger documentation for all routes.
